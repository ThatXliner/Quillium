## Key Implementation Details

### Provider Creation Pattern

```typescript
const { provider, awareness, ydoc, ytext } = await createYjsProvider(docId);
// provider: WebsocketProvider connected to relay
// awareness: Awareness instance for cursor sync
// ydoc: Y.Doc instance
// ytext: Y.Text("document") for CodeMirror binding
```

### JWT Auth in WebSocket Params

```typescript
new WebsocketProvider(PUBLIC_RELAY_URL, docId, ydoc, {
    params: { auth: session.access_token },
    connect: true,
});
```

### State Lifecycle

| Event | collabState transition |
|-------|----------------------|
| createYjsProvider called | disconnected -> connecting |
| provider.on("sync", true) | connecting -> connected |
| status disconnected | connected -> reconnecting |
| disconnectYjsProvider | any -> disconnected |

## Decisions Made

- **params.auth vs upgrade headers:** Used params.auth for simplicity - y-websocket passes these as query parameters which the relay can extract in the upgrade handler
- **Singleton pattern:** Module-level state (currentProvider, currentYdoc, currentDocId) matches existing socket.ts design
- **Sync vs status for "connected":** Wait for sync event rather than status="connected" - sync indicates actual data sync complete
