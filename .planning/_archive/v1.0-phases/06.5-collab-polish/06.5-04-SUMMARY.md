# Phase 06.5 Plan 04: Wire OwnerLeft and Cursors Summary

Wire ownerLeft handling and remote cursors into the existing collab client via socket event handlers and cursor extension composition.

## One-Liner

Socket event handlers for ownerLeft/clientLeft with setTimeout defer, cursor extension composed into enableCollab, and GoLiveButton reactive to ownerLeftSignal.

## Implementation Details

### Task 1: Socket Event Handlers and ownerLeftSignal

**store.ts**: Added `ownerLeftSignal` writable store that GoLiveButton subscribes to. When collabPlugin receives ownerLeft event, it increments this signal to notify UI components.

**collabPlugin.ts**: Added two new socket event handlers in the ViewPlugin constructor:

1. **ownerLeft handler**: Uses setTimeout to defer dispatch (avoiding CM update cycle recursion), reconfigures collabCompartment to empty, then increments ownerLeftSignal
2. **clientLeft handler**: Uses setTimeout to defer dispatch, dispatches removeRemoteCursor effect with the leaving client's ID

Both handlers check `this.destroyed` before and after setTimeout to prevent stale updates. The destroy() method now cleans up both listeners.

### Task 2: Cursor Extension Composition and GoLiveButton Wiring

**index.ts**: 
- Imports `createRemoteCursorsExtension` and `colorForClient` from cursors.ts (Plan 03)
- Re-exports `ownerLeftSignal` and cursor functions for external use
- Modified `enableCollab` to derive displayName from user metadata and compose both collab and cursor extensions in the compartment reconfigure

**GoLiveButton.svelte**:
- Added `disconnectCollab` and `ownerLeftSignal` to imports
- Added `$effect` that watches ownerLeftSignal: when incremented and isLive is true, calls disconnectCollab(), sets isLive = false, and shows "The owner ended the session" toast
