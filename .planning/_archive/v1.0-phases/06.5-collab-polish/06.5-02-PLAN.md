    ## Overview
    Brief explanation: Two repos, three services (Quillium app, relay server, Supabase).

    ## Prerequisites
    - bun installed
    - Rust toolchain (for Tauri)
    - Supabase CLI or existing Supabase project
    - Fly.io CLI (for production deployment only)

    ## 1. Supabase Setup
    - Create a Supabase project or use the existing one
    - Get SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY from Dashboard → Settings → API
    - Run database migrations from Phase 1 (point to `supabase/migrations/`)
    - Command to run migrations: `supabase db push` or link to existing project

    ## 2. Relay Server — Local Dev (quillium-landing repo)
    Commands:
    ```
    cd quillium-landing/relay
    cp .env.example .env   # or manually create .env
    ```
    .env content (exact keys):
    ```
    SUPABASE_URL=https://your-project.supabase.co
    SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
    PORT=3001
    ```
    ```
    bun install
    bun run dev
    ```
    Expected output: `[server] Relay listening on port 3001`

    ## 3. Quillium App — Local Dev
    ```
    cd Quillium
    cp .env.example .env.local   # or create manually
    ```
    .env.local content (exact keys):
    ```
    PUBLIC_SUPABASE_URL=https://your-project.supabase.co
    PUBLIC_SUPABASE_ANON_KEY=your-anon-key
    PUBLIC_RELAY_URL=http://localhost:3001
    ```
    ```
    bun install
    bun run tauri dev
    ```

    ## 4. Testing the Collab Session (Two Instances)
    Step-by-step:
    1. Start relay (step 2 above)
    2. Open Quillium instance A: `bun run tauri dev`
    3. Open Quillium instance B in second terminal: `bun run tauri dev`
    4. In instance A: sign up or log in → open a document → click "Go Live" → copy document ID
    5. In instance B: sign up/log in → click "⋯" menu → paste document ID → click Join
    6. Type in either instance — edits should appear in the other within ~100ms

    ## 5. Relay Server — Fly.io Deployment (Production)
    Prerequisites: `fly` CLI installed, Fly.io account.
    ```
    cd quillium-landing/relay
    fly launch --no-deploy       # creates fly.toml if not exists
    fly secrets set SUPABASE_URL=https://your-project.supabase.co
    fly secrets set SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
    fly deploy
    ```
    Expected output: App deployed to `https://your-relay.fly.dev`

    Update Quillium .env.local (or Tauri build config):
    ```
    PUBLIC_RELAY_URL=wss://your-relay.fly.dev
    ```

    ## 6. Bypassing Auth for Local Dev
    The relay supports `RELAY_SKIP_AUTH=1` environment variable for local testing without Supabase:
    ```
    RELAY_SKIP_AUTH=1 bun run dev
    ```
    Note: With RELAY_SKIP_AUTH, all connections are accepted without JWT validation.

    ## Environment Variable Reference
    Table with columns: Variable | Where Used | Where to Get It | Example Value
    Cover all variables from both repos.

    ## Troubleshooting
    - "Couldn't connect to relay server": check PUBLIC_RELAY_URL is set and relay is running
    - "Document not found" error: run Supabase migrations (sync_documents table must exist)
    - TypeScript errors in relay: run `bun run check` in relay directory
    - Two Tauri dev instances on same machine: each gets its own SQLite DB (different app data dirs by default)
