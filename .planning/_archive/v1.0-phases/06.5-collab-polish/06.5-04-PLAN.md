CRITICAL PATTERN (from RESEARCH.md Pitfall 2 and Pattern 6):
disableCollab() calls view.dispatch(). Never call view.dispatch() directly from inside a socket event handler
during a CM update cycle. Always defer with setTimeout:
```typescript
socket.on("ownerLeft", () => {
    if (this.destroyed) return;
    setTimeout(() => {
        disableCollab(this.view);
    }, 0);
});
```

For GoLiveButton, the ownerLeft event must also reset isLive. But collabPlugin is a CM ViewPlugin,
not a Svelte component. The clean pattern: emit a custom DOM event from collabPlugin that GoLiveButton listens to.
Alternatively, export a Svelte writable store `ownerLeftStore` that collabPlugin sets and GoLiveButton reads.
Use the store pattern (simpler, no DOM event needed):

In store.ts (or a new signal), add:
```typescript
export const ownerLeftSignal = writable(0); // increment to signal
```
collabPlugin increments ownerLeftSignal after setTimeout.
GoLiveButton subscribes with $effect and reacts when it increments.

        setTimeout(() => {

            // disableCollab imported from index.ts would create circular dep.
            // Instead: reconfigure compartment to empty (same as disableCollab's dispatch step).
            // Socket disconnect is handled separately by disconnectCollab after signal fires.
            this.view.dispatch({

            ownerLeftSignal.update((n) => n + 1);

    // Handle collaborator leaving: remove their cursor from remoteCursorsField
    socket.on("clientLeft", (data: { clientID: string }) => {
        if (this.destroyed) return;
        // clientLeft may arrive while a transaction is processing — defer to be safe
        setTimeout(() => {
            if (this.destroyed) return;
            this.view.dispatch({
                effects: removeRemoteCursor.of(data.clientID),
            });
        }, 0);
    });
