# Phase 6.5 Plan 01: Relay Owner Disconnect and Cursor Broadcast Summary

Relay-side changes enabling owner-disconnect kick (D-61) and cursor position broadcast (D-60) via socket.io events.

## One-liner

Added isOwner tracking to relay auth middleware with ownerLeft/clientLeft/cursorUpdate broadcast handlers.

## What Was Built

### Task 1: isOwner in socket.data + ownerLeft/clientLeft events

Extended `AuthenticatedSocketData` interface with `isOwner: boolean` field. The auth middleware now computes `isOwner = doc.owner_id === user.user.id` and stores it in `socket.data.isOwner` during handshake.

Modified `handleDisconnection` to:
1. Emit `clientLeft { clientID: userId }` to room on ANY disconnect (for cursor cleanup)
2. Emit `ownerLeft` to room ONLY when `socket.data.isOwner === true` (kicks collaborators per D-61)

Events are emitted BEFORE cleanup logic so `socket.to()` reaches remaining clients.

**Commit:** `5d3d012`

### Task 2: cursorUpdate relay handler

Added `socket.on("cursorUpdate", ...)` handler in `handleConnection` that:
- Receives `{ pos, name, color }` from client
- Broadcasts `{ clientID, pos, name, color }` to room via `socket.to(documentId).emit()`
- Injects `clientID: socket.data.userId` (relay-controlled, not client-supplied)

Cursors are ephemeral -- no room state mutation, just pass-through relay.

**Commit:** `3c24c47`

### Task 3: Unit tests

Created `owner.test.ts` with 7 passing tests covering:
- ownerLeft emitted only when `socket.data.isOwner === true`
- clientLeft emitted with correct clientID for all disconnects
- Room cleanup scheduling based on remaining socket count
- Security property documentation for cursorUpdate (clientID injection)

**Commit:** `13d7bca`
