<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> Supabase Auth | User-provided display name sent to Supabase |
| Anonymous JWT -> Relay | JWT from anonymous session used for WebSocket auth (future phase) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | signInAnonymously | accept | Anonymous users are inherently unverified; display name is self-selected per D-20. No PII involved. |
| T-03-02 | Tampering | displayName input | mitigate | Validate with Zod schema (2-50 chars, alphanumeric+spaces+hyphens+apostrophes). Trim whitespace. |
| T-03-03 | Information Disclosure | user_metadata | accept | Display name is intentionally visible to collaborators. No sensitive data stored. |
| T-03-04 | Denial of Service | anonymous signups | transfer | Supabase handles rate limiting on auth endpoints. |
</threat_model>
