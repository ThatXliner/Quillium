## Subtree storage shape

| Option | Description | Selected |
|--------|-------------|----------|
| Sibling Y.Map off ydoc | `ydoc.getMap('revisionSubtrees')` → `Y.Map<revId, Y.Map<vIdx, Y.Text>>`. Keeps current YjsAnnotation shape intact. | |
| Nested inside YjsAnnotation entry | Each annotation entry becomes a Y.Map with a `subtrees` child. Single-point lifecycle, bigger refactor. | ✓ |
| Flat composite key | `Y.Map<\`${revId}:${vIdx}\`, Y.Text>` on ydoc. Simplest lookups, manual cleanup. | |

**User's choice:** Nested inside YjsAnnotation entry.
**Notes:** Drove the follow-up on how deep the Y.Map conversion goes.

### Follow-up: YjsAnnotation Y.Map scope

| Option | Description | Selected |
|--------|-------------|----------|
| Text fields Yjs, threads as Y.Array, metadata plain | Version bodies + comment bodies → Y.Text. Thread → Y.Array<MessageObject> sorted on read. Metadata stays plain. | ✓ |
| Text fields Yjs, threads stay JSON string | Bodies → Y.Text, thread still JSON.stringify. | |
| Only version bodies Yjs | Narrowest scope. | |

**User's choice:** Text fields Yjs, threads as Y.Array, metadata plain.
**Notes:** Users can't edit other users' messages, so threads only need append-ordering by timestamp — Y.Array suffices.

## UndoManager scoping

| Option | Description | Selected |
|--------|-------------|----------|
| One UndoManager per subtree | Each nested editor has its own isolated stack. Per-editor scope. | |
| Global UndoManager tracking all Y.Texts | Single manager tracking ytext + ymap + all subtrees. | ✓ (refined) |
| Dynamic trackedTypes | Swap tracked types on focus change. | |

**User's choice:** Global UndoManager — "global for you: you can't undo other people's changes (standard Yjs behavior)."
**Notes:** User noted this matches typical per-user undo. Standard Yjs `trackedOrigins: ["local"]` already filters peers; the question was only about whether the user's own stack is unified or per-editor. Unified won.

### Follow-up: Cross-editor undo UX

| Option | Description | Selected |
|--------|-------------|----------|
| Just undo silently | Ctrl-Z walks local stack; if change lands in non-focused editor, user doesn't see it. | |
| Undo and auto-navigate | Open/scroll to the non-focused editor so user sees the change. | ✓ |

**User's choice:** Undo and auto-navigate.
**Notes:** Best UX at the cost of wiring undo → navigation events.

## Version switch semantics (resolved inline, no AskUserQuestion)

**User's framing:** "active version only dictates what's used in the main/parent doc. A peer
editing a diff version can still continue editing that diff version. If they want to select
their version as the main version, just click the pill again."

**Decision (D-99):** `activeVersionIndex` is cosmetic metadata (which version renders inline
in the parent doc). It does NOT lock peer editing — each version is an independent subtree.
No coordination needed. Pill click = local rendering change only.
