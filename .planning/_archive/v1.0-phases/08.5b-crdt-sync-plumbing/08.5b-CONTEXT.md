# Phase 8.5: CRDT Subtrees for Nested Editors - Context

**Gathered:** 2026-04-18
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the JSON-stringified version-blob sync in `syncRevisionChanges`
(currently in `src/lib/collab/yjsAnnotations.ts`) with dedicated Y.Text
subtrees per revision version. Annotations become recursive Y.Map nodes
whose text bodies are Y.Text instances — so concurrent peer edits inside
a nested editor merge character-by-character (same semantics as main doc),
not last-writer-wins.

In scope:
- Version body text → Y.Text per version (character-level CRDT merge)
- Comment body text → Y.Text (for comments whose body is editable)
- Comment threads → Y.Array<MessageObject> (append-only, sorted by timestamp on read)
- Nested annotations inside a nested editor (recursive structure)
- Per-user global UndoManager covering all Y.Texts (main + every subtree)
- Undo auto-navigation when Ctrl-Z lands in a non-focused editor

Out of scope:
- Peer cursor rendering inside nested editors (deferred to v2)
- Any backwards-compatibility with Phase 8 wire format (never shipped)

</domain>

<decisions>
## Implementation Decisions

### Data Structure
- **D-90:** YjsAnnotation converts from plain JSON object to a `Y.Map` with children.
  Shape (recursive): `{ text: Y.Text, thread: Y.Array<MessageObject>, annotations: Y.Map<YjsAnnotation>, ...plainMetadata }`.
  Metadata fields (id, anchorPos, colorHint, activeVersionIndex, annotationGeneration, etc.) stay as plain stored values.
- **D-91:** Revision versions are stored as entries in a `versions: Y.Map<vIdx, Y.Map>`.
  Each version Y.Map has `{ text: Y.Text, annotations: Y.Map<YjsAnnotation> }`.
  No separate sibling map on the ydoc — subtrees live inside the annotation they belong to.
  (Chose "Nested inside YjsAnnotation entry" over sibling Y.Map off ydoc.)
- **D-92:** Recursive structure: annotations inside a nested editor use the same Y.Map shape.
  Same code path works at arbitrary nesting depth; no compound-scope routing needed.
- **D-93:** Comment threads are `Y.Array<MessageObject>` (append-only). No concurrent edit is possible
  because users can only edit their own messages, so conflict resolution is trivial: sort by timestamp on read.

### Migration
- **D-94:** No migration code. Phase 8 annotation sync was never shipped to users,
  so there is no existing wire format to preserve. Phase 8.5 simply defines the new
  shape; legacy `JSON.stringify(versions)` path gets removed wholesale.

### Undo
- **D-95:** One global `Y.UndoManager` per user, tracking `ytext` + top-level `ymap` + every
  subtree Y.Text. `trackedOrigins: new Set(["local"])` keeps it per-user (per D-74).
  Ctrl-Z walks the local stack chronologically across editors. You cannot undo other
  users' edits (standard Yjs per-user undo; nothing changes there).
- **D-96:** When Ctrl-Z undoes an edit in a nested editor that is not currently focused,
  auto-navigate/scroll to that revision so the user sees the change. Implementation: wire
  an "undo target" event from the UndoManager to the navigation system (open revision modal
  or scroll inline editor into view).
- **D-97:** Subtree Y.Texts added to UndoManager `trackedTypes` on creation. Research item:
  confirm how Y.UndoManager handles dynamically-added tracked types — may need reconstruction
  or may work via origin-only filtering. Planner/researcher to verify against current yjs docs.

### Cursors
- **D-98:** Peer cursor rendering inside nested editors is out of scope for v1.
  Main editor cursor sync (existing Phase 7.5 awareness extension) continues unchanged.
  Nested-editor cursor sync deferred to v2 (see deferred ideas).

### Version Switch Semantics
- **D-99:** `activeVersionIndex` is metadata about which version renders inline in the
  parent — NOT a lock on which version peers can edit. Each version Y.Text is independent;
  a peer can be typing in v0 while the owner is viewing/editing v2. Clicking a version's
  pill sets that version as active locally; there is no "owner broadcasts active version"
  ceremony. If a user wants their version to be the one rendered inline, they click its
  pill. If they change their mind, they click the other pill back.

### Claude's Discretion
- Exact Y.Map key layout for metadata fields (plain stored values) vs. Y.Map get/set semantics
- Whether `annotationGeneration` field is still needed once subtrees provide CRDT ordering
  (planner to evaluate — may be obsoleted)
- Internal origin tags for distinguishing local vs. remote subtree mutations in `NestedEditorController`
- How `createYjsBinding` reuse vs. specialization for subtrees is structured (research first)

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `createYjsBinding(ytext)` from `src/lib/collab/yjsBinding.ts` — the Y.Text ↔ CodeMirror
  delta-op binding. Should work unchanged when applied to a subtree Y.Text; NestedEditorController
  just needs to install it on the nested EditorView alongside the existing extensions.
- `codeMirrorToYjsAnnotation` / `yjsAnnotationToCodeMirror` — converter functions. Will be
  rewritten for the new recursive Y.Map shape but the pattern stays the same.
- `AnnotationIdMap` — CM-id ↔ Y-id tracking; likely reusable with minor extensions for nested scopes.
- `createAnnotationSyncPlugin` ViewPlugin pattern — bidirectional Y.Map ↔ CM sync. The recursion means
  nested editors get their own plugin instance operating on their subtree's ymap child.

### Established Patterns
- Origin-based loop prevention: `ydoc.transact(..., "local")` + `yjsAnnotationSync` CM annotation.
  Must extend to subtree mutations — nested editor local writes tagged `"local"`, remote writes
  distinguished accordingly.
- Per-keystroke sync (main doc): Y.Text observe → CM dispatch with `yjsAnnotation` marker.
  Same pattern for each subtree.
- Per-editor history via CodeMirror was replaced by Y.UndoManager in Phase 7.5; subtrees follow
  suit (no CM history on nested editors either).

### Integration Points
- `enableCollab` in `src/lib/collab/index.ts` — currently creates one binding, undo, awareness,
  annotationSync set. Subtree wiring is on-demand (at nested editor mount time), not at collab-enable.
- `NestedEditorController.create()` — where a nested editor's subtree binding gets installed.
- `NestedEditorController.destroy()` — where subtree binding / per-subtree UndoManager participation
  gets torn down.
- `translateAndDispatch` and `flushAnnotationStateToParent` — the existing upward sync paths.
  With subtrees, `translateAndDispatch` becomes unnecessary for doc text (the subtree IS the source
  of truth, shared directly via Y.Text). `flushAnnotationStateToParent` may also collapse since
  sub-annotations live in the subtree's own ymap, not serialized into the parent blob.

</code_context>

<specifics>
## Specific Ideas

- **Version switch is cosmetic, not authoritative.** Clicking a version pill changes local
  rendering. Other peers keep editing whatever version they were editing. No coordination needed.
- **Thread append semantics:** messages are never edited by other users; a Y.Array append is always
  safe. Sort by timestamp on read. This matches Slack / Discord / iMessage behavior (chronological,
  per-author).
- **Nested-within-nested is automatic via recursion.** Since every annotation has the same
  `{text, thread, annotations}` shape, N-deep nesting works without special cases. The nested
  editor controller just installs bindings against whatever subtree it was opened over.
- **D-83 extends naturally.** The global UndoManager already tracks `[ytext, ymap]` (Phase 8 D-83).
  Phase 8.5 extends `trackedTypes` to include subtree Y.Texts as they come into existence.
- **`annotationGeneration` may be obsoleted.** Phase 8 uses it to detect when nested sub-annotations
  changed so the outer editor knows to rebuild. With subtree Y.Maps broadcasting changes via
  observers, this bookkeeping field may no longer be necessary. Planner to evaluate.

</specifics>

<deferred>
## Deferred Ideas

- **Peer cursors inside nested editors (v2).** Extend awareness state with a `focus` field
  `{ kind: 'main' } | { kind: 'nested', revId, vIdx, relPos }` so each nested editor can render
  peer cursors whose focus matches its identity. Requires the main awareness extension to be
  scope-aware.
- **Thread message editing by original author.** If a user wants to edit their own past comment,
  that would require either converting thread entries to Y.Texts or keeping them plain but
  swapping by message id. Out of scope — the current data model treats messages as immutable
  once posted.
- **Undo auto-navigate UX polish.** When Ctrl-Z lands in a non-focused editor, we open/scroll to it.
  Future polish: toast/banner "Undid edit in revision X" for better transparency.

</deferred>
