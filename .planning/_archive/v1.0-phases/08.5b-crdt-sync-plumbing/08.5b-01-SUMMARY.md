# Phase 08.5b Plan 01: Scoped observeDeep Annotation Sync Summary

Rewrote createAnnotationSyncPlugin to operate on a scoped (ytext, annotations-Y.Map) pair via observeDeep, enabling recursive annotation trees.

## One-liner

Scoped observeDeep-driven annotation sync with Y.Array.push for threads, deleting the legacy JSON-stringified versions path.

## Changes Made

### Task 1: Rewrite createAnnotationSyncPlugin as scoped, observeDeep-driven sync

**Commits:** cf96af0

Replaced the entire body of `yjsAnnotations.ts`:

1. **New factory signature:** `createAnnotationSyncPlugin(scopeYtext, scopeAnnotations, clientId)` - scope-agnostic, works at any recursion depth (main editor or nested revision version body)

2. **Remote -> CM via observeDeep:** Single `scopeAnnotations.observeDeep(handler)` subscription replaces the previous shallow `ymap.observe()`. Event routing algorithm:
   - If `event.target === scopeAnnotations` (shallow Y.Map event): handle add/remove/update of annotation nodes
   - If `event.target instanceof Y.Array && event.path[1] === "thread"`: dispatch `updateThread` effect
   - All other nested events (version Y.Text changes, label edits, nested annotations): schedule full annotation rebuild via remove + add

3. **CM -> Remote via transact("local"):** All local writes wrapped in `ydoc.transact(() => {...}, "local")` for origin tagging. Observer short-circuits on `tr.origin === "local"`.

4. **Y.Array.push for threads (D-93):** The `updateThread` effect handler uses `threadArr.push(appended)` for the append happy path. Falls back to atomic replace (delete + push) if thread shrinks.

5. **syncRevisionChanges DELETED (D-94):** The entire private method that did JSON.stringify(versions) diffing is removed. Revision version text is now the subtree Y.Text's responsibility.

6. **All JSON.stringify/JSON.parse eliminated:** No JSON calls in the rewritten code (verified via grep).
