# Phase 7.5: Yjs Migration - Context

**Gathered:** 2026-04-17
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace OT (@codemirror/collab) with Yjs CRDT for more robust sync. Client uses custom Yjs-CodeMirror binding, relay uses y-websocket-server pattern, documents sync correctly between multiple clients, concurrent edits converge without version mismatch errors, per-user undo works via Yjs UndoManager, existing features (cursors, owner disconnect) preserved, awareness protocol replaces custom cursor sync.

</domain>

<decisions>
## Implementation Decisions

### Migration Strategy
- **D-70:** Clean migration — remove @codemirror/collab entirely, no feature flag or gradual rollout. Rip out OT completely.

### Relay Server
- **D-71:** Replace Socket.io relay with y-websocket-server — use standard y-websocket-server package with custom auth hook in upgrade handler. Rewrite auth integration (JWT validation, Supabase permissions), rewrite persistence to use Yjs state encoding. Lives in quillium-landing repo.

### Client Binding
- **D-72:** Custom Yjs-CodeMirror integration — build our own binding using Y.Text and awareness protocol directly (y-codemirror.next is unmaintained). Replace existing `cursors.ts` with awareness-based cursor implementation. Integrate with CodeMirror 6 via ViewPlugin pattern.

### Persistence
- **D-73:** Supabase Postgres persistence — custom adapter using `Y.encodeStateAsUpdate()` / `Y.applyUpdate()` to store Yjs state in existing tables. Reuse `collab_updates` table structure or adapt as needed. Aligns with Phase 9 offline queue plans.

### Per-User Undo
- **D-74:** Client-side UndoManager — each client creates its own `Y.UndoManager` scoped to local Y.Text, tracking only its own origin. Matches current per-user undo behavior from D-50.

### Preserved Behaviors (from prior phases)
- **D-57:** Live Room mode — session ends when owner leaves (Phase 6)
- **D-60:** Google Docs-style cursors with name labels (Phase 6.5) — now via awareness protocol
- **D-61:** No warning before kick on owner disconnect (Phase 6.5)
- **D-54:** Dual-write local SQLite persistence continues during collab (Phase 6)

### Claude's Discretion
- Y.Text vs Y.XmlText choice for document representation
- Awareness state schema (user name, color, cursor position fields)
- Exact wire protocol between client and y-websocket-server
- How to handle document initialization (empty doc vs pull existing state)
- Cursor color assignment strategy (deterministic vs random)

</decisions>
