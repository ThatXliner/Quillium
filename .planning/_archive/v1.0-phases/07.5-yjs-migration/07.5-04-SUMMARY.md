### Sync Protocol Implementation

`sync.ts` implements the y-websocket server pattern:
- MESSAGE_SYNC (0): Y.Doc state sync via `syncProtocol.readSyncMessage`
- MESSAGE_AWARENESS (1): Cursor/presence via `awarenessProtocol.applyAwarenessUpdate`
- MESSAGE_CUSTOM (3): Owner disconnect notification

### Threat Mitigations Applied

Per T-07.5-07 (Tampering mitigation):
- Wrapped `syncProtocol.readSyncMessage` in try-catch
- Wrapped `awarenessProtocol.applyAwarenessUpdate` in try-catch
- Disconnects client on malformed sync data

### Persistence Strategy

Per D-73, persistence uses:
- `Y.encodeStateAsUpdate(ydoc)` for full state snapshots
- `Y.applyUpdate(ydoc, update)` for loading state
- Base64 encoding for Uint8Array -> Postgres bytea
- Two tables: `yjs_documents` (snapshots), `yjs_updates` (incremental)

## Key Files

### sync.ts

Exports:
- `setupYjsConnection(ws, room, clientData, onUpdate)` - Main connection handler
- `MESSAGE_SYNC`, `MESSAGE_AWARENESS`, `MESSAGE_CUSTOM` - Message type constants
- `CUSTOM_OWNER_LEFT`, `CUSTOM_CLIENT_LEFT` - Custom subtypes

Features:
- Sends sync step 1 (state vector) on connection
- Broadcasts Y.Doc updates to all other clients
- Handles awareness updates for cursor sync
- Owner disconnect kicks all collaborators (D-57, D-61)

### yjsUpdates.ts

Exports:
- `persistYjsState(documentId, ydoc)` - Full state snapshot
- `persistYjsUpdate(documentId, update)` - Incremental update
- `loadYjsState(documentId)` - Load state + incremental updates
- `clearYjsUpdates(documentId)` - Cleanup after snapshot
