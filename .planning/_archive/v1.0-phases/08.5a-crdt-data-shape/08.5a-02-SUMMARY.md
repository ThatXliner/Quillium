## Accomplishments

- Removed the legacy `YjsAnnotation` flat interface from `types.ts` and replaced it with `YjsAnnotationNode = Y.Map<unknown>` (D-90/D-92) plus a collab-owned `MessageObject` (D-93).
- Rewrote `codeMirrorToYjsAnnotation` to build a fresh Y.Map populated with `Y.Text`, `Y.Array`, and nested `Y.Map` children inside a single `ydoc.transact(..., "init")` — peers never observe a partially assembled node.
- Rewrote `yjsAnnotationToCodeMirror` to read recursive Y.Map children directly via `instanceof Y.Array / Y.Map / Y.Text` guards, returning `null` on malformed data (T-08.5-02-01/04).

- Converted 5 `annotation-tree.test.ts` scaffolds to real tests: recursive shape integrity, two-doc version propagation, thread ordering, `activeVersionIndex` clamp, null-selection via an unrelated doc.

## Decisions Made

- **VersionState.annotationGeneration stays at 0 on decode.** Plan 8.5c-01 owns the full removal of this field; this plan keeps `annotationGeneration: 0` in the converter output so the CM-side annotation shape is unchanged and no Plan 8.5c-01 code is needed to pass this plan's tests.
- **"Null selection when anchored text deleted" is tested against an independent Y.Doc.** Yjs's RelativePosition resolution does NOT return null when anchored items are merely deleted in the same doc (documented in `relativePosition.test.ts` with "returns null or collapsed when anchored text is fully deleted"). The converter's `null` path only fires when items are unreachable. Decoding against an unrelated doc genuinely exercises that path.
- **Version-propagation test uses a standalone two-Y.Doc setup, not `twoPeerHarness.makePeer`.** The harness installs `createAnnotationSyncPlugin`, which is in `yjsAnnotations.ts` (owned by Plan 8.5b-01) and still expects the legacy flat shape. Loading the plugin would crash during the observer firing on the new recursive shape. The standalone two-doc setup exercises pure converter propagation without the plugin.

## Deviations from Plan

The plan's `action` blocks were implemented line-for-line in `types.ts` and `annotationSchema.ts`. Test wiring deviated slightly from the plan's per-test wording in three places; all three were forced by runtime behavior observed during execution. None of these changed the coverage intent (shape integrity / propagation / ordering / clamp / null selection).

### Auto-fixed Issues

**1. [Rule 1 - Bug] Shape-integrity test rewrote to integrate-before-read**
- **Found during:** Task 2 test wiring.
- **Issue:** Detached Y.Maps (returned by the converter before the caller calls `ymap.set`) log `Invalid access: Add Yjs type to a document before reading data.` and return `undefined` from `.get(...)`. The plan's per-test spec read children directly from the converter return value, which made `instanceof Y.Array / Y.Map` all return false.
- **Fix:** Added a `buildAndIntegrate()` helper that sets the node into a host `ymap` inside a `ydoc.transact` then re-reads it via `ymap.get(key)`. All 4 buildAndIntegrate-using tests read the post-integration node.
- **Files modified:** `src/lib/collab/annotation-tree.test.ts`
- **Verification:** `bun run test:run src/lib/collab/annotation-tree.test.ts` — 5 passed, 1 todo.
- **Committed in:** `c408df8` (Task 2 commit)

**2. [Rule 1 - Bug] Version-propagation test uses standalone two-Y.Doc setup instead of twoPeerHarness**
- **Found during:** Task 2 test wiring.
- **Issue:** `makePeer` installs `createAnnotationSyncPlugin` (file: `yjsAnnotations.ts`, owned by Plan 8.5b-01), which still expects the legacy flat `YjsAnnotation` shape. When the observer fires on a new recursive-shape `ymap.set`, the plugin's conversion call path crashes the test harness during Yjs update serialization.
- **Fix:** Replaced the `makePeer/connect/teardown` calls with a standalone two-Y.Doc pair whose updates are piped bidirectionally by a local `aToB`/`bToA` pair. This keeps the test's intent (cross-doc propagation) while avoiding the pre-migration plugin. The harness itself is untouched and remains usable by 8.5b-01 after it fixes `yjsAnnotations.ts`.
- **Files modified:** `src/lib/collab/annotation-tree.test.ts`
- **Verification:** Test now passes.
- **Committed in:** `c408df8` (Task 2 commit)

**3. [Rule 1 - Bug] Null-selection test uses unrelated-doc decode instead of same-doc delete**
- **Found during:** Task 2 test wiring.
- **Issue:** `relativeToAbsolute` in Yjs does NOT return null when the anchored range is deleted in the same doc — it collapses to the deletion point (`{from: 0, to: 0}`). This is documented in `relativePosition.test.ts` under "returns null or collapsed when anchored text is fully deleted". The plan's "delete the anchored text" wording asserted `null` but the actual converter returns a non-null annotation with a collapsed selection.
- **Fix:** Instead of deleting text in the source doc, the test decodes the node against an independent `Y.Doc` that never received the anchor-owning client's items. This is the real-world "unreachable anchor" path that `relativeToAbsolute` returns null for.
- **Files modified:** `src/lib/collab/annotation-tree.test.ts`
- **Verification:** Test asserts `decoded === null`; passes.
- **Committed in:** `c408df8` (Task 2 commit)

## Issues Encountered

- **Yjs prelim-content gotcha.** Detached Y.Maps store child Y types as prelim content that cannot be read via `.get()` until the parent is integrated into a Y.Doc hierarchy. This drove the `buildAndIntegrate()` helper (see deviation 1). Documented in the test file header and the helper's JSDoc for future consumers.
- **Two-doc update serialization crash inside makePeer.** The plugin observer that still assumes the flat shape triggered a `TypeError: Cannot read properties of undefined (reading 'length')` in `_writeVarStringNative` during Yjs transaction cleanup. This is the proximate reason the version-propagation test avoids `twoPeerHarness`. It will resolve automatically when Plan 8.5b-01 rewrites `yjsAnnotations.ts`.
